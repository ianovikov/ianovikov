# Цифровой онбординг клиентов банка - портфолио системного/бизнес-аналитика

Демонстрационный проект (вымышленная тема, любые совпадения случайны), показывающий полный аналитический цикл - от бизнес-требований до API-контракта и SQL-аналитики - на примере системы полностью удалённого открытия банковского счёта.

## Структура

| Папка | Артефакт | Что показывает |
|---|---|---|
| [`BRD`](./01-brd) | Business Requirements Document | Бизнес-цели, scope, 21 функц. + 10 нефункц. требований, риски, критерии приёмки |
| [`Use case`](./02-use-case) | UML Use Case диаграмма | Акторы, сценарии, `<<include>>`/`<<extend>>` связи |
| [`BPMN`](./03-bpmn) | BPMN 2.0 схема процесса | Дорожки по ролям, параллельные проверки, бизнес-правила прямо на схеме |
| [`ERD`](./04-erd) | ERD базы данных | Структура таблиц и связи между ними |
| [`API`](./05-api-spec) | OpenAPI 3.1 спецификация | REST-контракты для регистрации, верификации, открытия счёта |
| [`SQL`](./06-sql-portfolio) | Интерактивные SQL-кейсы | 6 запросов  с реальным выполнением в браузере |

## Сквозная логика проекта

Все артефакты связаны одной сущностью — заявкой на онбординг: **BRD** описывает требования → **BPMN** показывает процесс → **Use Case** детализирует сценарии взаимодействия → **ERD** фиксирует структуру данных → **API-спека** формализует контракт между системами → **SQL-кейсы** показывают, как эти данные анализируются после запуска.
